DOCUMENTACAO DO BACKEND - ECOTAG API
====================================

Projeto: EcoTag
Tipo: API RESTful ASP.NET Core em C#
Framework: .NET 10
Banco de dados: PostgreSQL via Entity Framework Core
Documentacao interativa: Swagger
URL padrao da API em desenvolvimento: http://localhost:5295
URL do Swagger: http://localhost:5295/swagger


1. VISAO GERAL
==============

O backend EcoTag permite cadastrar usuarios, autenticar via JWT, gerenciar veiculos, registrar passagens de tag, calcular CO2e evitado, consultar dashboard de impacto, simular cenarios sustentaveis, consultar gamificacao e visualizar ranking.

A ideia principal do sistema e comparar dois cenarios:

- Sem tag: veiculo para, espera em fila/cabine, consome combustivel parado/acelerando e pode gerar ticket em papel.
- Com tag: passagem continua, sem parada.

Cada passagem registrada gera automaticamente um valor de CO2e evitado em kg.


2. AUTENTICACAO E AUTORIZACAO
=============================

O sistema usa JWT Bearer Token.

Fluxo:

1. Cadastrar usuario:
   POST /api/auth/register

2. Fazer login:
   POST /api/auth/login

3. Copiar o token retornado.

4. Enviar nas rotas protegidas usando o header:
   Authorization: Bearer SEU_TOKEN

No Swagger:

1. Clique em "Authorize".
2. Cole o token JWT.
3. Confirme.
4. Teste as rotas protegidas.

Regras de permissao:

- Rotas publicas:
  - POST /api/auth/register
  - POST /api/auth/login

- Rotas de usuario autenticado:
  - Perfil
  - Veiculos
  - Passagens
  - Dashboard
  - Simulador
  - Gamificacao
  - Ranking

- Rotas de admin:
  - /api/admin/fatores-emissao
  - /api/admin/parametros-cenario
  - /api/admin/locais-uso

Observacao importante:
O cadastro comum cria usuarios com role "user".
Para testar rotas admin, promova um usuario diretamente no banco:

UPDATE "Users" SET "Role" = 'admin' WHERE "Email" = 'email@teste.com';

Depois faca login novamente para gerar um token com a role atualizada.


3. PADRAO DE RESPOSTAS
======================

Codigos HTTP usados pela API:

200 OK
Usado em consultas, login, atualizacoes e simulacoes bem sucedidas.

201 Created
Usado quando um recurso e criado.

204 No Content
Usado quando um recurso e excluido com sucesso.

400 Bad Request
Usado quando a request tem dados invalidos, regra de negocio violada ou valor fora do permitido.

401 Unauthorized
Usado quando a rota exige token e o token nao foi enviado, esta invalido ou expirou.

403 Forbidden
Usado quando o usuario esta autenticado, mas nao tem permissao de admin.

404 Not Found
Usado quando o recurso solicitado nao existe ou nao pertence ao usuario autenticado.

Formato comum de erro:

{
  "message": "Descricao do erro."
}

5. FORMULA DE CALCULO DE CO2e EVITADO
=====================================

Ao registrar uma passagem, o sistema calcula automaticamente o CO2e evitado.

Formula:

tempoParadoHoras =
((tempoMedioFilaMinutos * 60) + tempoEsperaCabineSegundos) / 3600

litrosEvitados =
(consumoMarchaLenta * tempoParadoHoras) + consumoAdicionalAceleracao

co2EvitadoKg =
(litrosEvitados * fatorEmissao) + emissaoTicketPapelKg

O resultado e arredondado para 6 casas decimais.

Campos envolvidos:

- tempoMedioFilaMinutos: parametro por tipo de local.
- tempoEsperaCabineSegundos: parametro por tipo de local.
- emissaoTicketPapelKg: parametro por tipo de local.
- consumoMarchaLenta: fator por combustivel.
- consumoAdicionalAceleracao: fator por combustivel.
- fatorEmissao: multiplicador de emissao por combustivel.


6. ROTAS DE AUTENTICACAO
========================

6.1 POST /api/auth/register
---------------------------

O que faz:
Cadastra um novo usuario comum.

Autenticacao:
Nao precisa de token.

Request body:

{
  "nome": "Roger",
  "email": "roger@email.com",
  "password": "123456"
}

Campos:

- nome: obrigatorio, maximo 100 caracteres.
- email: obrigatorio, formato de email, maximo 150 caracteres.
- password: obrigatorio, minimo 6 caracteres.

Regras:

- O email e salvo em minusculo.
- A senha nao e salva em texto puro; e salva como hash BCrypt.
- A role inicial sempre e "user".
- Se o email ja existir, retorna erro.

Response 201:

{
  "id": 1,
  "nome": "Roger",
  "email": "roger@email.com",
  "role": "user",
  "createdAt": "2026-05-30T12:00:00Z"
}

Possiveis retornos:

- 201: usuario criado.
- 400: dados invalidos ou email ja cadastrado.


6.2 POST /api/auth/login
------------------------

O que faz:
Autentica o usuario e retorna um token JWT.

Autenticacao:
Nao precisa de token.

Request body:

{
  "email": "roger@email.com",
  "password": "123456"
}

Campos:

- email: obrigatorio, formato de email.
- password: obrigatorio.

Response 200:

{
  "token": "TOKEN_JWT_AQUI",
  "user": {
    "id": 1,
    "nome": "Roger",
    "email": "roger@email.com",
    "role": "user",
    "createdAt": "2026-05-30T12:00:00Z"
  }
}

Possiveis retornos:

- 200: login realizado.
- 401: email ou senha invalidos.

- 201: passagem criada.
- 400: fator ou parametro ambiental ausente/invalido.
- 401: token ausente ou invalido.

======================

------------------------

Simula CO2e evitado sem salvar historico.

{

  "passagensPorDia": 10,
  "totalPassagens": 300,
  "co2EvitadoPorPassagemKg": 0.150917,
  "co2EvitadoTotalKg": 45.275100,

Possiveis retornos:

- 400: premissas ambientais ausentes ou dados invalidos.

- 404: veiculo do usuario ou local de uso nao encontrado.

13. ROTAS DE RANKING
====================

13.1 GET /api/ranking?periodo=mensal&limit=10
---------------------------------------------

O que faz:
Retorna ranking mensal de sustentabilidade com base no CO2e evitado no mes atual.

Autenticacao:
Precisa de token JWT.

Query params:

- periodo: opcional. Atualmente aceita apenas mensal. Padrao: mensal.
- limit: opcional. Quantidade maxima de itens. Minimo 1, maximo 100. Padrao: 10.

Regras:

- Soma as passagens do mes atual.
- Ordena por CO2e evitado de forma decrescente.
- Em caso de empate, ordena por nome.
- Pontos sustentaveis = floor(co2EvitadoKg * 100).

Response 200:

{
  "periodo": "mensal",
  "inicio": "2026-05-01T00:00:00Z",
  "fim": "2026-06-01T00:00:00Z",
  "itens": [
    {
      "posicao": 1,
      "userId": 1,
      "nome": "Roger",
      "co2EvitadoKg": 3.500000,
      "pontosSustentaveis": 350
    }
  ]
}

Possiveis retornos:

- 200: ranking calculado.
- 400: periodo invalido.
- 401: token ausente ou invalido.


14. ROTAS ADMIN - FATORES DE EMISSAO
====================================

Estas rotas sao protegidas por role admin.

Motivo:
Fatores de emissao sao premissas globais do motor de calculo. Alterar esses dados muda os resultados ambientais das passagens futuras.


14.1 GET /api/admin/fatores-emissao
-----------------------------------

O que faz:
Lista todos os fatores de emissao por combustivel.

Autenticacao:
Precisa de token JWT com role admin.

Request:
Nao possui body.

Response 200:

[
  {
    "tipoCombustivel": "gasolina",
    "fatorEmissao": 2.31,
    "consumoMarchaLenta": 0.8,
    "consumoAdicionalAceleracao": 0.015
  }
]

Possiveis retornos:

- 200: lista fatores.
- 401: token ausente ou invalido.
- 403: usuario sem role admin.


14.2 GET /api/admin/fatores-emissao/{tipoCombustivel}
-----------------------------------------------------

O que faz:
Busca um fator pelo combustivel.

Parametro de rota:

- tipoCombustivel: gasolina, etanol ou diesel.

Response 200:

{
  "tipoCombustivel": "gasolina",
  "fatorEmissao": 2.31,
  "consumoMarchaLenta": 0.8,
  "consumoAdicionalAceleracao": 0.015
}

Possiveis retornos:

- 200: fator encontrado.
- 400: combustivel invalido.
- 401: token ausente ou invalido.
- 403: usuario sem role admin.
- 404: fator nao encontrado.


14.3 POST /api/admin/fatores-emissao
------------------------------------

O que faz:
Cria um novo fator de emissao.

Request body:

{
  "tipoCombustivel": "gasolina",
  "fatorEmissao": 2.31,
  "consumoMarchaLenta": 0.8,
  "consumoAdicionalAceleracao": 0.015
}

Campos:

- tipoCombustivel: obrigatorio, gasolina/etanol/diesel.
- fatorEmissao: obrigatorio, maior que 0.
- consumoMarchaLenta: obrigatorio, maior ou igual a 0.
- consumoAdicionalAceleracao: obrigatorio, maior ou igual a 0.

Regras:

- Nao permite cadastrar combustivel duplicado.

Possiveis retornos:

- 201: fator criado.
- 400: payload invalido ou fator ja existente.
- 401: token ausente ou invalido.
- 403: usuario sem role admin.


14.4 PUT /api/admin/fatores-emissao/{tipoCombustivel}
-----------------------------------------------------

O que faz:
Atualiza um fator de emissao existente.

Parametro de rota:

- tipoCombustivel: combustivel que sera atualizado.

Request body:

{
  "tipoCombustivel": "gasolina",
  "fatorEmissao": 2.40,
  "consumoMarchaLenta": 0.85,
  "consumoAdicionalAceleracao": 0.016
}

Regras:

- O tipoCombustivel da rota deve ser igual ao tipoCombustivel do body.
- Nao permite tipos fora da lista aceita.

Possiveis retornos:

- 200: fator atualizado.
- 400: dados invalidos.
- 401: token ausente ou invalido.
- 403: usuario sem role admin.
- 404: fator nao encontrado.


14.5 DELETE /api/admin/fatores-emissao/{tipoCombustivel}
--------------------------------------------------------

O que faz:
Remove um fator de emissao.

Regras:

- Nao permite excluir fator usado por veiculos.

Possiveis retornos:

- 204: fator removido.
- 400: fator em uso ou tipo invalido.
- 401: token ausente ou invalido.
- 403: usuario sem role admin.
- 404: fator nao encontrado.

  {
    "id": 1,
    "nome": "Pedagio Demo",
    "tipoLocal": "pedagio"
  }
]

Possiveis retornos:

16.2 GET /api/admin/locais-uso/{id}
-----------------------------------

Possiveis retornos:

- 200: local encontrado.
- 401: token ausente ou invalido.
- 403: usuario sem role admin.
- 404: local nao encontrado.


16.3 POST /api/admin/locais-uso
-------------------------------

O que faz:
Cria local de uso.

Request body:

{
  "nome": "Pedagio BR Demo",
  "tipoLocal": "pedagio"
}

Campos:

- nome: obrigatorio, maximo 100 caracteres.
- tipoLocal: obrigatorio, pedagio/estacionamento.

Regras:

- O tipoLocal precisa ter parametros ambientais cadastrados.

Possiveis retornos:

- 201: local criado.
- 400: payload invalido ou tipoLocal sem parametros.
- 401: token ausente ou invalido.
- 403: usuario sem role admin.


16.4 PUT /api/admin/locais-uso/{id}
-----------------------------------

O que faz:
Atualiza nome e tipo de um local.

Request body:

{
  "nome": "Estacionamento Shopping Demo",
  "tipoLocal": "estacionamento"
}

Regras:

- O tipoLocal precisa ter parametros ambientais cadastrados.

Possiveis retornos:

- 200: local atualizado.
- 400: dados invalidos.
- 401: token ausente ou invalido.
- 403: usuario sem role admin.
- 404: local nao encontrado.


16.5 DELETE /api/admin/locais-uso/{id}
--------------------------------------

O que faz:
Remove um local de uso.

Regras:

- Nao permite excluir local com passagens registradas.

Possiveis retornos:

- 204: local removido.
- 400: local possui passagens registradas.
- 401: token ausente ou invalido.
- 403: usuario sem role admin.
- 404: local nao encontrado.

20. OBSERVACOES PARA DEFESA DO PROJETO
======================================

- Controllers apenas recebem requisicoes e retornam respostas HTTP.
- Services concentram regras de negocio e validacoes.
- DTOs separam entrada/saida dos Models do banco.
- JWT protege rotas de usuario e diferencia admin por role.
- EF Core aplica migrations e acessa PostgreSQL.
- Calculo de CO2e e feito no backend, evitando manipulacao pelo cliente.
- Simulador nao salva historico.
- Ranking e gamificacao usam passagens realmente registradas.
- Rotas admin existem para alterar premissas ambientais sem mudar codigo-fonte.
